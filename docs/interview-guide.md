# 项目演示备忘

本文件用于准备现场讲解。描述实现时，以仓库代码和本地演示行为为准；生产方案应明确说成后续设计。

## 简历摘要

设计并实现图文带货智能选品原型：用 Pandas、NumPy 清洗商品并构造结构化特征，结合规则过滤、商品潜力评分、热点语义匹配和图文场景匹配形成可解释推荐；以 FastAPI 提供推荐、内容草稿、回流及数据源接口，React 管理台展示完整业务闭环。项目采用模拟数据，支持离线演示、角色权限和自动化验收。

## 现场演示顺序

1. 登录管理台，说明管理员、运营、观察员的权限范围。系统登录不等于抖音平台授权。
2. 在“数据源接入”分别连接并同步商品与热点，指出快照 ID、有效记录数和来源标记。正式 API 入口当前处于待审批状态，不会发起真实平台请求。
3. 在“热点趋势”选择一个热点并进入选品工作台，说明热点和商品数据均来自模拟 JSON。
4. 调整规则阈值，运行推荐；展示清洗统计、硬规则过滤原因、三项分数、推荐理由和模型来源。
5. 打开商品详情、AI 解释和图文草稿，说明生成内容要经业务审核。
6. 将推荐商品带入“投放回流”，提交模拟曝光、点击、成交与退款，再用相同事件 ID 演示去重。
7. 生成训练快照，指出目前只记录待训练样本与模拟评估状态，没有训练真实 LightGBM 模型。

## 技术边界

- **AI 开发：**定义清洗与特征、实现潜力评分和热点匹配、约束模型输出、记录模型版本、设计真实图文转化模型的训练与评估。
- **后端：**接口契约、鉴权、数据源适配、持久化、事件幂等、限流与审计。
- **前端：**管理台路由、状态管理、阈值和数据源操作、推荐解释与回流展示。

默认离线模式用可解释的加权逻辑模拟商品潜力评分；千问适配器可用于文本理解和内容生成。多模态离线模式使用类目图片描述和文本相似度，不等于直接读取图像。生产可在获得真实图文投放样本后训练 LightGBM，并根据授权和成本选择视觉模型。

## 常见追问

**为什么不用爬虫？** 本项目的目标是验证选品链路和接口边界。正式数据必须经过平台授权和数据使用审批；商品和热点可能需要分别申请接口权限。

**图文和短视频能共用转化模型吗？** 商品基础特征可以复用，素材特征与转化标签应分开。图文更依赖首图、标题和静态场景；短视频还涉及开头留存、播放时长等信号。

**转化样本不均衡怎么办？** 先定义曝光口径和转化观察窗口，按时间切分避免未来信息泄漏；再比较样本权重或负样本下采样，并检查 PR-AUC、Top-K 效果和概率校准。

**如何证明模型有效？** 离线评估排序质量和概率校准；线上在获得真实数据和发布权限后，用 A/B 测试比较点击、成交、退款和单位佣金收益，按类目与素材形态分层。

**如何降低模型幻觉？** 将数值决策与生成内容分开：规则和结构化模型负责硬约束与排序，LLM 输出按 schema 校验，生成文案需核对商品资质并保留人工审核。
